# Подходы к построению маршрутов (логистических цепочек) Россия → Тбилиси

Задача: не «найти билет A→B», а найти **самый дешёвый способ оказаться в Тбилиси**,
включая варианты, которые ни один агрегатор не покажет одной строкой: перелёт в третью
страну + отдельно купленное второе плечо, горячий тур с чартером, перелёт до Владикавказа
+ маршрутка через границу.

Текущий режим по умолчанию — **только авиасообщение** (`search.include_ground: false`).
Всё, что ниже сказано про наземные плечи и класс D, описывает реализованное поведение,
которое включается одним флагом, но в выдачу сейчас не попадает.

---

## 1. Города вылета из РФ: как отбирать «логистически удобные»

Полный перебор всех аэропортов РФ бессмысленен и дорог по запросам. Отбор идёт по трём
фильтрам, в этом порядке:

1. **Есть прямой рейс в Грузию** — Москва (MOW: VKO/ZIA), Сочи (AER), Минеральные Воды (MRV),
   Екатеринбург (SVX).
2. **Есть дешёвый выход на наземный коридор** — Владикавказ (OGZ, до КПП Верхний Ларс
   ~30 км, до Тбилиси 148 км по Военно-Грузинской дороге), Минеральные Воды и Сочи как
   альтернативные точки входа в тот же коридор.
3. **Есть дешёвый выход на авиахаб** — Москва, Санкт-Петербург (LED), Казань (KZN),
   Екатеринбург (SVX), Новосибирск (OVB), Краснодар/Ростов (при работающих аэропортах) —
   оттуда в EVN / GYD / IST / MSQ / ALA / DXB.

Всё остальное подключается только как «подвоз»: если пользователь живёт не в этих
городах, трекер добавляет внутреннее плечо до ближайшего опорного города, но считает
его стоимость честно (и это часто убивает экономию).

**Опорные города вылета по умолчанию** (конфиг `origins`): MOW, LED, AER, MRV, SVX, KZN.
Владикавказ (OGZ) в списке появляется вместе с `include_ground`: без наземного плеча
оттуда до Тбилиси не добраться — рейсов OGZ→TBS не существует.

## 2. Точки входа в Грузию

- **TBS** (Тбилиси) — целевая точка.
- **KUT** (Кутаиси) — дешёвые лоукостеры (Wizz), дальше поезд/маршрутка до Тбилиси (~4 ч).
- **BUS** (Батуми) — дальше поезд Батуми–Тбилиси (~5 ч, 20–30 ₾).
- **Наземный вход**: КПП Дарьяли / Верхний Ларс (единственный работающий автомобильный
  переход из РФ), далее Степанцминда → Тбилиси.

Прибытие в KUT/BUS считается валидным финишем только вместе с наземным плечом до Тбилиси
— иначе сравнение цен нечестное.

## 3. Классы цепочек

| Класс | Схема | Типичный смысл |
|---|---|---|
| **A. Прямой** | MOW/AER/MRV/SVX → TBS | Базовая линия; Азимут / Red Wings / Georgian Airways |
| **B. Одна авиастыковка (единый билет)** | RU → hub → TBS одним билетом | Защищён перевозчиком, дороже |
| **C. Self-transfer (виртуальный интерлайн)** | RU → hub (билет 1) + hub → TBS (билет 2) | Основной источник экономии; риск на пассажире |
| **D. Авиа + наземное плечо** | RU → OGZ + маршрутка через Верхний Ларс; RU → EVN + автобус; RU → KUT/BUS + поезд | Часто абсолютный минимум цены; сейчас выключено флагом `include_ground` |
| **E. Пакетный тур** | горячий тур с чартером в Грузию | Иногда дешевле сухого билета — сравнивается по фактической цене пакета |
| **F. Open-jaw / асимметрия** | туда через Ереван, обратно прямым | Экономия на обратном плече |

Отдельно фиксируем то, что трекер **не** делает: hidden-city (билет с пересадкой в TBS
и выходом там) — формально дешевле, но нарушает правила перевозки, ломается с багажом
и приводит к аннулированию обратного плеча. Такие варианты помечаются и не попадают
в рекомендации.

## 4. Хабы и коридоры

Хаб включается в перебор, если через него исторически есть дешёвая связка в TBS:

- **EVN (Ереван)** — только вместе с наземным плечом: рейса EVN→TBS нет, а автобус идёт
  5–7 ч. В авиарежиме хаб бесполезен и из конфига исключён.
- **IST / SAW (Стамбул)** — Turkish/AJet/Pegasus, огромная ёмкость.
- **GYD (Баку)** — AZAL; учитывать особенности наземной границы.
- **MSQ (Минск)** — Belavia, без визовых сложностей.
- **DXB / SHJ (ОАЭ)** — flydubai/Air Arabia, работает при акциях.
- **ALA / NQZ (Казахстан)** — SCAT/Air Astana, актуально для Сибири и Урала.
- **AYT/Анталия и другие «туристические»** — только в контексте чартеров.

Каждый коридор в конфиге имеет `enabled`, лимит запросов и требования (нужна ли виза/транзит,
можно ли платить российской картой).

## 5. Алгоритм: как это считается

### 5.1 Мультимодальный граф

Узлы — города (MOW, OGZ, EVN, TBS, …) плюс «псевдоузлы» границы (`LARS`).
Дуги — плечи (`Leg`) с атрибутами: режим (`air` / `bus` / `train` / `taxi`), цена,
валюта, время вылета/прилёта, источник, тип цены (`live`/`cached`/`estimate`),
можно ли оплатить российской картой, требуется ли виза.

### 5.2 Перечисление путей (до запросов к API)

Сначала строим **топологические кандидаты** — пути длиной до `max_legs` (по умолчанию 3)
из множества `origins` в `destinations`, где промежуточные узлы ∈ разрешённые хабы.
Каждый кандидат проверяется двумя фильтрами:

- **Detour-фильтр**: сумма great-circle расстояний по пути ≤ `detour_factor` (по умолчанию 2.2)
  × прямое расстояние. Отсекает бессмысленные «через Владивосток».
- **Фильтр здравого смысла**: пути с двумя подряд наземными плечами, с возвратом в тот же
  город, с запрещёнными коридорами.

Это ключевой шаг для экономии бюджета запросов: вместо `|origins| × |hubs| × |dates|`
полного перебора остаётся десятки-сотни осмысленных пар «плечо + окно дат».

### 5.3 Запрос цен по плечам

Для каждого уникального плеча (city_from, city_to, окно дат) вызываются провайдеры
параллельно, результаты нормализуются: валюта → ₽, дедупликация по
(перевозчик, номер рейса, дата, цена ± 1%), отсечение мусора (цена ниже
`sanity_min_price` или выше `sanity_max_price`).

### 5.4 Склейка плеч в цепочку

Для каждого топологического кандидата собираем цепочки динамическим программированием
по времени: плечо `L2` присоединяется к `L1`, если

```
L1.arrive + MCT(mode, self_transfer, airport_change) <= L2.depart <= L1.arrive + max_layover
```

Параметры стыковки (конфиг `connections`):

- `min_connection_same_ticket` — 60–90 мин для единого билета;
- `min_connection_self_transfer` — 3–4 ч (получить багаж, повторный чек-ин, риск задержки);
- `min_connection_airport_change` — +2–3 ч (IST↔SAW, VKO↔ZIA);
- `min_connection_border` — 3–5 ч для наземной границы Верхний Ларс (очереди — норма);
- `max_layover` — 24 ч по умолчанию; ночная стыковка добавляет стоимость отеля.

DP хранит для каждого префикса пути Pareto-множество состояний
(накопленная цена, время прибытия) — это позволяет не терять варианты «дороже, но быстрее».

### 5.5 Полная стоимость, а не цена билета

Ранжирование идёт по **обобщённой стоимости**:

```
к оплате = Σ цена_плеча
         + Σ стоимость_трансферов (аэропорт↔город, граница)
         + багаж (если тариф без багажа, а он нужен)
         + отель за ночную стыковку (если layover > overnight_threshold)

ранжирование = к оплате
             + риск-надбавка за self-transfer (P(срыв) × стоимость перебронирования)
             + время × time_value_per_hour
```

Для пакетного тура «цена плеча» — это цена всего пакета: столько денег и уходит.
Включённые в него отель и обратный перелёт в формуле не участвуют вообще, поэтому тур за
20 000 ₽ обгоняет билет за 25 000 ₽ просто по цене, а тур за 34 900 ₽ проигрывает билету
за 13 806 ₽ и не может отыграться за счёт бонусов. Состав пакета виден во флагах
`hotel_included` и `return_included`, но на числа не влияет.

Риск-надбавка — это то, что отличает «честный» трекер от наивного: два отдельных билета
с 1.5-часовой стыковкой дешевле, но при срыве второе плечо теряется полностью. В конфиге
задаются `self_transfer_failure_prob` и `rebooking_cost` — и вариант либо остаётся
выгодным после надбавки, либо нет.

### 5.6 Выдача

- **Топ-N по обобщённой стоимости** — что рекомендовать.
- **Pareto-фронт (цена, длительность)** — для тех, кто готов доплатить за скорость.
- **Абсолютный минимум цены** — рекорд, даже если он неудобный (нужен как ориентир).

## 6. Мониторинг во времени (собственно «трекер»)

Разовый поиск бесполезен: цена Россия→Тбилиси гуляет в 2–3 раза. Логика мониторинга:

1. **Регулярные прогоны** (например, 3–6 раз в сутки) по всем окнам дат из конфига.
2. **История в SQLite**: каждое наблюдение цены пишется с `observed_at`, источником и
   типом цены. Дальше считаются baseline'ы: минимум за всю историю, p10/p25/медиана
   за последние N дней по маршруту.
3. **Детекторы**:
   - цена ниже целевого порога из конфига (`target_price`);
   - цена ниже p10 истории маршрута;
   - падение более чем на X% относительно предыдущего наблюдения;
   - появление нового коридора/перевозчика, которого раньше не было.
4. **Подтверждение**: если сигнал пришёл из кэш-источника (Travelpayouts), перед алертом
   делается контрольный запрос к живому источнику (Duffel / SerpApi / сайт перевозчика).
   Это убивает 90% ложных срабатываний.
5. **Алерты** — консоль, webhook, Telegram; с дедупликацией (один и тот же вариант не
   алертится дважды в течение `alert_cooldown_hours`).

## 7. Управление бюджетом запросов

Ограничители, встроенные в планировщик:

- окна дат разрежаются: сначала месячный календарь (`grouped_prices`), потом точные
  запросы только по дням-кандидатам с минимумом;
- плечи кэшируются на `cache_ttl_minutes`, повторные прогоны переиспользуют кэш;
- «горячие» коридоры (те, что давали минимум за последние 30 дней) опрашиваются чаще,
  холодные — реже (adaptive polling);
- жёсткий лимит запросов на прогон и на источник, с приоритетом Тир-1.

## 8. Практические ограничения, которые влияют на маршруты

- **Виза/транзит**: транзит через Стамбул и ОАЭ для российского паспорта — без визы при
  соблюдении правил стерильной зоны; при self-transfer с получением багажа может
  потребоваться въезд в страну. Для Армении/Беларуси/Казахстана въезд безвизовый.
- **Правила въезда в Грузию** — безвизовый режим до 1 года; при наземном въезде из РФ
  проверяется отсутствие въездов в Абхазию/Южную Осетию с российской стороны.
- **Оплата**: западные перевозчики и Duffel требуют иностранную карту — цепочка
  помечается флагом, иначе выдача «дешёвых» вариантов будет фиктивной.
- **Багаж**: у Победы/Wizz/Pegasus базовый тариф без багажа; сравнение без учёта багажа
  систематически занижает лоукостеры.
- **Ночь на границе**: Верхний Ларс работает круглосуточно, но очереди грузовиков и
  праздники дают +3–8 ч. Поэтому наземное плечо всегда считается с буфером.

## 9. Приоритеты реализации

1. Прямые рейсы (класс A) как baseline для сравнения.
2. Self-transfer через IST и подвоз до AER/MRV (класс C) с риск-надбавкой.
3. Наземный коридор Владикавказ → Тбилиси (класс D) — реализован, но выключен
   (`include_ground`); при включении там обычно и лежит минимум цены.
4. Горячие туры (класс E) — по цене пакета, наравне с билетами.
5. Open-jaw (класс F) — как отдельный режим поиска «туда-обратно».
