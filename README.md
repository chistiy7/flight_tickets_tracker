# Трекер дешёвых маршрутов Россия → Тбилиси

Отслеживает не «билет A→B», а **самый дешёвый способ долететь до Тбилиси**: собирает цены
из нескольких источников (агрегаторы, прямые сайты авиакомпаний, горячие туры), склеивает
из них логистические цепочки с учётом реальных стыковок и полной стоимости поездки, ведёт
историю цен и алертит на падения.

По умолчанию трекер ищет **только авиасообщение**. Наземные плечи (маршрутка через Верхний
Ларс, автобус Ереван → Тбилиси, поезда внутри Грузии) реализованы, но выключены:
`search.include_ground: true` плюс провайдер `ground` возвращают их вместе с цепочками
класса D.

Два документа отвечают на основные вопросы:

- **[docs/sources.md](docs/sources.md)** — список источников цен: режим доступа, что отдают
  (живая цена / кэш), лимиты, юридические ограничения, минимально достаточный набор для старта.
- **[docs/routing.md](docs/routing.md)** — подходы к построению маршрутов: отбор городов
  вылета, классы цепочек, правила стыковок, алгоритм, расчёт полной стоимости, мониторинг.
- **[docs/collector.md](docs/collector.md)** — свой парсер: почему сбор отделён от поиска,
  контракт склада офферов, политика свежести цен, границы применимости.

## Почему просто «поискать билет» недостаточно

Прямые рейсы Москва → Тбилиси (Азимут, Red Wings, Georgian Airways) стоят от ~13 000 ₽,
но реальный минимум обычно лежит в другом месте:

- вылет не из Москвы: прямые рейсы из Сочи и Мин. Вод дешевле, а подвоз до них — копеечный;
- горячий тур с чартером, где пакет с отелем и обратным перелётом дешевле билета в одну сторону;
- два отдельных билета через Стамбул или Кутаиси;
- с `include_ground` — перелёт во Владикавказ (~6 500 ₽) плюс маршрутка через Верхний Ларс.

Ни один агрегатор не покажет это одной строкой: плечи продаются в разных системах и не
связаны единым билетом. Трекер собирает такие цепочки сам и сравнивает их честно —
с трансферами, багажом, ночёвками и риском сорвать стыковку на двух отдельных билетах.

## Быстрый старт

```bash
pip install -r requirements.txt
pip install -e .            # добавит команду tbs-tracker

# Офлайн-демо: без токенов и без сети, данные из data/fixtures/demo_offers.json
tbs-tracker -c config/demo.yaml run
```

Пример вывода (демо-данные):

```
Маршрут                   Вылет        В пути          Цена  Заплатить  Кл  Источники / флаги
AER → TBS                 06.10 06:30  1ч 25м          6891       9891   A  aviasales | baggage_extra
MRV → TBS                 07.10 23:55  1ч 10м          7902      10902   A  aviasales | baggage_extra
MOW → TBS                 06.10 09:00  3ч 30м         11900      11900   E  tourvisor | package_tour, hotel_included, return_included
MOW → TBS                 07.10 17:00  3ч 15м         13806      16806   A  aviasales | baggage_extra
MOW → AER → TBS           05.10 07:10  24ч 45м        11091      20591   C  aviasales | self_transfer, overnight_layover, baggage_extra
MOW → IST → TBS           05.10 15:00  14ч 15м        25890      32390   C  aviasales, duffel | requires_foreign_card
```

«Цена» — сумма плеч, «Заплатить» — реальные деньги (плечи + трансферы + багаж + ночная
стыковка). «Кл» — класс цепочки (A — прямой рейс, C — self-transfer, E — пакетный тур,
D — с наземным плечом, если оно включено; см. [docs/routing.md](docs/routing.md)).

Ниже таблицы идут детали, и там у каждого плеча своя ссылка — плечи цепочки покупаются
по отдельности:

```
MOW → AER → TBS | класс C (self-transfer (два билета))
  • MOW→AER 05.10 07:10 DP DP401 4200₽ [aviasales, cached]
      искать: https://www.aviasales.ru/search/MOW0510AER1
  • AER→TBS 06.10 06:30 WZ WZ557 6891₽ [aviasales, cached]
      искать: https://www.aviasales.ru/search/AER0610TBS1
  стыковки: 20ч 55м
  стоимость: плечи 11091₽ + трансферы 0₽ + багаж 6000₽ + ночёвки 3500₽ = 20591₽ к оплате
```

Глагол в подсказке — не украшение, а тип ссылки: **купить** — страница покупки,
**искать** — поисковая выдача, где нужный рейс ещё предстоит найти (и цена может
отличаться), **смотреть** — описание, которое к покупке не ведёт вовсе (так Tourvisor
отдаёт карточку отеля, а сам пакет бронируется у агента по номеру тура). Если ссылки
нет совсем — как у Duffel, где бронь создаётся запросом к API, — вместо неё выводится
номер оффера. Сколько вариантов расписывать подробно, задаёт `--details` (по умолчанию 3);
в `--json` ссылки есть у всех вариантов.

Боевой запуск:

```bash
cp config/config.example.yaml config/config.yaml
export TRAVELPAYOUTS_TOKEN=...        # бесплатный токен, широкое покрытие рынка РФ
tbs-tracker run
```

## Команды

| Команда | Что делает |
|---|---|
| `tbs-tracker run` | Полный прогон: цены → цепочки → история → алерты. `--json`, `--limit`, `--details`, `--no-alerts`, `--no-store` |
| `tbs-tracker collect` | Сбор цен на склад офферов, без сборки цепочек. `--status` — состояние склада, `--keep-stale` — не вычищать старое |
| `tbs-tracker routes` | Топология маршрутов и план запросов, **без обращения к сети**. `--queries` |
| `tbs-tracker sources` | Какие источники включены и чего им не хватает (токен, справочники) |
| `tbs-tracker history` | История наблюдений; `--best` — рекорды по маршрутам; `--route MOW>OGZ>TBS` |
| `tbs-tracker places` | Справочник городов и обоснование, почему город в списке вылета |

## Как это работает

```
enumerate_paths      топология: осмысленные цепочки городов (до max_legs)
      ↓              detour-фильтр отсекает крюки
leg_queries          уникальные запросы «плечо + окно дат», отсортированные по приоритету
      ↓
providers            параллельный опрос источников; нет токена — мягкий skip, не падение
      ↓
normalize            валюты → ₽, дедупликация, отсечение неправдоподобных цен
      ↓
assemble_itineraries склейка плеч с проверкой стыковок (MCT, граница, смена аэропорта)
      ↓              Pareto-прунинг по (цена, время прилёта)
compute_cost         полная стоимость: трансферы, багаж, ночёвки, риск self-transfer, цена времени
      ↓
store (SQLite)       история наблюдений по плечам и цепочкам
      ↓
alerts               цель / p10 истории / падение на X% → консоль, Telegram, webhook
```

Ключевые решения, которые отличают трекер от наивного сравнения цен:

- **Полная стоимость вместо цены билета.** Победа за 6 500 ₽ без багажа с ночной стыковкой —
  это не 6 500 ₽, а 6 500 + багаж + отель + трансфер между аэропортами.
- **Туры сравниваются по телу пакета.** Цена тура встаёт в общий ряд с ценами билетов как
  есть: пакет за 20 000 ₽ выгоднее билета за 25 000 ₽, потому что денег уходит меньше.
  Включённые отель и обратный перелёт цену не уменьшают и не увеличивают — никаких
  зачётов и настроек для них нет. Флаги `hotel_included` и `return_included` просто
  показывают, что за те же деньги вы получаете больше.
- **Риск self-transfer оцифрован.** Два отдельных билета с тугой стыковкой получают
  надбавку `P(срыв) × стоимость перебронирования`, поэтому не выигрывают формально.
- **Тип цены хранится честно.** У каждого плеча есть `price_kind`: `live` (можно купить),
  `cached` (кэш чужих поисков Aviasales, живёт 2–7 дней), `estimate` (справочная цена
  наземного плеча). Алерт по неживой цене явно требует подтверждения.
- **Граница считается как граница.** Если включить наземные плечи, переход Верхний Ларс
  получает буфер 4 часа (`min_border_min`) и запас в длительности: очереди — норма.
- **Бюджет запросов.** У источников квоты (Tourvisor — 3000 поисков/сутки), поэтому есть
  жёсткий потолок запросов на прогон, файловый кэш и приоритезация плеч.

## Подключение источников

Провайдеры включаются в секции `providers` конфига. Каждый деградирует мягко: нет токена —
источник помечается как пропущенный, остальные работают.

| Провайдер | Доступ | Цена | Что закрывает |
|---|---|---|---|
| `travelpayouts` | бесплатный токен | кэш | Широкое покрытие рынка РФ, календарь цен |
| `airline_direct` | конфигурируется вручную | живая | Азимут / Red Wings / Georgian Airways — финальная цена |
| `duffel` | self-serve (test → live) | живая | Turkish, Pegasus, Wizz, flydubai (плечи через хабы) |
| `serpapi_google_flights` | платный self-serve | живая | Арбитр расхождений между источниками |
| `tourvisor` | JWT + подписка | кэш | Горячие туры: пакет с отелем и обратным перелётом часто дешевле билета в одну сторону |
| `ground` | справочник + Яндекс.Расписания | оценка | Выключен: Владикавказ→Тбилиси, Ереван→Тбилиси, поезда в Грузии |
| `collector` | свой склад офферов | как собрали | Цены, собранные парсером: там, где API не существует ([docs/collector.md](docs/collector.md)) |
| `fixtures` | файл | как в файле | Офлайн-демо и тесты |

Полный список источников (включая те, что требуют партнёрских договоров, и те, что закрылись —
Amadeus Self-Service отключён 17.07.2026, Kiwi Tequila стал invite-only) — в
[docs/sources.md](docs/sources.md).

## Ключи доступа

Ключи передаются только через переменные окружения — в конфиге лежит имя переменной
(`token_env`), а не сам секрет. Имя можно переопределить, если у вас другая схема
именования. Нет ключа — источник помечается пропущенным, прогон продолжается.

| Переменная | Для чего | Где взять | Цена |
|---|---|---|---|
| `TRAVELPAYOUTS_TOKEN` | Кэш цен Aviasales — единственный обязательный ключ | [travelpayouts.com](https://www.travelpayouts.com/) → регистрация в партнёрской программе → Инструменты → API, токен виден сразу | Бесплатно |
| `DUFFEL_TOKEN` | Живые офферы Turkish, Pegasus, Wizz для плеч через хабы | [duffel.com](https://duffel.com/) → Dashboard → Developers → Access tokens; тестовый режим сразу, live после верификации компании | Бесплатно, комиссия при выписке |
| `SERPAPI_KEY` | Google Flights как арбитр расхождений в цене | [serpapi.com](https://serpapi.com/) → Dashboard → Your API Key | ~100 запросов/мес бесплатно, дальше платно |
| `TOURVISOR_JWT` | Горящие туры | [api.tourvisor.ru](https://api.tourvisor.ru/) → договор турагента → ЛК → JWT; дополнительно нужны `country_id` и `departure_ids` из справочников `/countries` и `/departures` | Подписка, разделы оплачиваются отдельно |
| `YANDEX_RASP_APIKEY` | Расписания автобусов и поездов для наземных плеч | [yandex.ru/dev/rasp](https://yandex.ru/dev/rasp/) → получить ключ | Бесплатно для некоммерческого использования |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Алерты в Telegram | Токен — у [@BotFather](https://t.me/BotFather), chat_id — у [@userinfobot](https://t.me/userinfobot) или через `getUpdates` | Бесплатно |
| `ALERT_WEBHOOK_URL` | Алерты в свой сервис | Ваш эндпоинт | — |

Ключей не требуют: `airline_direct` (нужны эндпоинты сайтов в конфиге, а не токен),
`ground` без расписаний (статический справочник) и курсы ЦБ РФ.

## Свой парсер вместо ключей

Там, где API не существует (рублёвые тарифы Азимута и Red Wings, российские OTA), цену
можно снимать самостоятельно. Сбор при этом отделён от поиска: парсинг медленный и
ломкий, а прогон должен оставаться быстрым и повторяемым.

```bash
tbs-tracker collect            # источники → склад офферов (по расписанию, отдельно)
tbs-tracker collect --status   # что лежит на складе и насколько оно свежее
tbs-tracker run                # склад → цепочки → алерты (быстро, без сети)
```

Склад — SQLite-файл (или ваш HTTP-сервис), его читает провайдер `collector`. Опрос своего
склада не тратит бюджет внешних запросов. Возраст записи становится частью цены: свежая
сохраняет свой тип, пролежавшая дольше `fresh_minutes` превращается в `cached`, старше
`max_age_minutes` — не отдаётся вовсе.

Наполнять склад может как сам трекер (`collect`, включая декларативный парсер
`airline_direct` — эндпоинт и пути до полей задаются в конфиге, без кода), так и внешний
парсер на чём угодно: ему достаточно писать строки в таблицу `offers` или отвечать на
HTTP-запрос трекера. Контракт, режимы подключения и границы применимости (ToS, антибот,
стоимость прокси) — [docs/collector.md](docs/collector.md).

## Регулярный запуск

Трекер имеет смысл только как периодический прогон. Пример для cron (4 раза в сутки):

```cron
0 */6 * * * cd /opt/tbs-tracker && /usr/bin/env TRAVELPAYOUTS_TOKEN=... \
  ./.venv/bin/tbs-tracker -c config/config.yaml run >> logs/run.log 2>&1
```

История и рекорды копятся в SQLite (`runtime.db_path`), алерты дедуплицируются по
`alerts.cooldown_hours`, поэтому частые прогоны не превращаются в спам.

## Ограничения

- `airline_direct` требует ручной настройки эндпоинтов: у каждого перевозчика свой
  внутренний JSON, и автоматический опрос сайта обычно противоречит его ToS. По умолчанию
  провайдер выключен; легальная альтернатива — партнёрский доступ.
- Собственный парсер (`collector`) снимает ограничение «нет партнёрского договора — нет
  цены», но не снимает ToS площадок, антибот-защиту и расходы на прокси. Смысл он имеет
  точечно — на 3–5 перевозчиках прямых рейсов и паре российских OTA, а не на всём рынке.
- Наземные плечи по умолчанию выключены (`search.include_ground: false`) — сейчас трекер
  ищет только авиасообщение. Когда они включены, их цены остаются справочными диапазонами
  (`estimate`): живых API с ценами маршруток через Верхний Ларс не существует.
- Трекер не выписывает билеты и сознательно не предлагает hidden-city схемы.
- Поиск строится в одну сторону (РФ → Тбилиси); режим open-jaw «туда-обратно» описан в
  docs/routing.md как следующий шаг, но не реализован.
